Quant’s room uses the existing public Anything browser port. The public Anything engine is ported to this local browser room; the Python reference is documented separately.

Read. Then choose.

Web access starts off. When you turn it on, a native HTTPS GET receives the response as inert data. The reader selectively keeps readable text, document boundaries and safe link destinations. It does not give the source HTML to a page runtime, and website CSS, images, scripts, forms, cookies and trackers are not rendered there.

Quant render is an optional choice for each page. You approve one of four local layouts and whether its text may update manually, every minute or every five minutes. Quant starts from nothing executable and builds a new page from the extracted wording, safe HTTPS routes and the app’s integrity-pinned original artwork. A route or update is always a fresh cookie-free native GET. The rebuilt page is not saved, cannot write to Quant’s memory and is not used to teach him.

A site whose useful text exists only after JavaScript runs will not appear in this mode. That is a deliberate safety boundary. Render website design is a separate choice for a restricted selection of source HTML plus styles and images from that page’s HTTPS origin. Those resources can make additional GET requests. Scripts are blocked by default. A separate choice for the current page can enable bounded inline JavaScript; external scripts stay blocked. Forms, frames, media and website downloads stay blocked, so many sites will be incomplete.

You decide what leaves.

Only GET requests are available. POST, uploads and form submissions are blocked. The app provides no listening server or incoming endpoint.

Keep what belongs to you.

Up to 32 selected Books and three selected Contexts inform Quant. A checked .quantbook is a real portable memory file; a selected Context also updates source-linked Book continuity. Original source files are read as copies. Save Quant keeps a portable copy through a native save dialog. Clear visit clears the browser visit without clearing Quant’s room.

Websites do not automatically teach Quant, access his memory or change your reading preferences. Local room storage is not separately encrypted by Quant.

Clear limits.

The native client must receive the server’s response before it can extract text; “text only” describes what survives into the reader, not what the server is required to send. Your GET still reaches the destination. Certificate errors are not overridden. HTTPS does not prove a site is harmless or protect a compromised device or trust store. The app is not an anonymity service or an exploit-proof browser. Its native builds and adversarial-page behaviour still require testing on their respective operating systems.
